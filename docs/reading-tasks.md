# 阅读任务模块：业务与表设计

更新日期：2026-11-19

## 1. 当前范围与状态

- 目标：老师发布阅读任务，学生阅读、查词、按释义加入学习并创建卡片。
- 当前讨论业务、计时协议和接口，尚未开始阅读模块业务编码。已确认规则见第 2、3 节及第 4.2 节；计时接口约定与其余接口草案见第 4.3 节，下一步见第 5.1 节。
- 初始化脚本已补充 `articles`、`reading_tasks`、`reading_stats`；`learning_cards` 因 `sense_id` 类型未定暂未建表。尚未应用到现有数据库或执行建表验证，脚本修改不会自动迁移已有数据库卷。
- 词典数据待用户提供，释义 ID 的类型、稳定性、词典外键、词性、词形还原和查词响应映射暂缓确定。
- FSRS、例句生成和复习流程留到后续阶段，已确认方向保留在第 6 节。

交接时先读第 5.1 节定位接续点，再查第 4.2 节发布幂等规则和第 2.2 节计时规则；需要实现时再核对第 3 节及第 5.2 节代码入口。本文记录设计结论，标为“已确认”不代表代码已实现。新对话默认继续规划；用户明确要求实现后再开始业务编码。

## 2. 已确认的业务规则

### 2.1 任务与文章

- 一个任务属于一个班级、对应一篇文章。任务与文章分表，各有独立自增 ID；本期每个新任务创建新文章，不提供文章复用或文章库入口，结构保留未来扩展空间。
- 界面先填写任务，再上传或粘贴正文，最后统一提交；任务和文章在同一事务保存成功后即发布。
- 标题最多 50 字、正文最多 5,000 字，去除首尾空白后均不能为空；阅读要求可选，无单独字数上限。
- 上传、发布老师取登录身份，上传班级取任务所属班级并校验老师权限；这些历史归属创建后不覆盖。
- 发布后可改标题、阅读要求和正文；正文修改只影响当前文章，在同一事务更新任务和文章的 `updated_at`，保留已有统计和卡片首次来源。
- 同一正文再次布置也创建新任务、新文章，任务统计从零开始；已加入释义不因重新布置而再次计数。
- 不做草稿、截止时间、归档、隐藏、完成提交或自动完成判定；不保存正文版本，不跟踪划词位置。

### 2.2 阅读统计与计时

- 实际进入阅读页并通过权限检查后，仅建立 Redis 阅读状态，不创建零值统计。首次合法正数时长入库时创建统计，已有记录则累加；有效查词、首次加入释义仍可独立创建统计。列表查询或详情预加载不创建统计。
- 页面在前台且未连续 1 分钟无操作时，每约 30 秒发送一次“仍在阅读”心跳；离开前台或静读超时后停止发送，恢复后按正常周期继续。
- 每个页面实例在浏览器内存中生成一个 `windowId`，进入请求重试和后续心跳沿用该 ID；刷新或打开新页面会生成新 ID。请求只传 `windowId`，不传客户端累计秒数、`permitId` 或计时幂等 key。
- 90 秒没有心跳时阅读状态过期。过期状态下的心跳提示“阅读状态已失效，请刷新页面重试”；刷新后重新进入并创建状态。
- 进入和心跳成功均返回 `204`；业务错误使用 `detail.code` 与 `detail.message`，参数校验错误使用 `422` 的 `detail` 数组，具体约定见下文。网络或临时服务故障不当作接管，客户端继续按正常 30 秒周期发送，不快速补偿。
- 班级和任务权限只在进入时检查，不在每次心跳重验；心跳仍验证登录身份。退班或班级删除后，已打开的页面仍可继续心跳；离开页面后重新访问仍按当前权限检查。
- `reading_stats.updated_at` 在新增阅读秒数成功入库、有效查词或首次加入释义时更新，表示最近统计更新时间，可反映最近阅读活动；不另存首次、最近阅读时间。

进入请求的 Redis 状态处理（均不写阅读统计）：

| 当前状态 | 处理 |
| --- | --- |
| 无状态 | 保存 `windowId`、当前整秒时间戳作为计时起点，设置 90 秒过期 |
| 状态有效且 `windowId` 相同 | 直接返回 `204`，不修改时间戳或过期时间 |
| 状态有效且 `windowId` 不同 | 本次进入接管，重设时间戳及 90 秒过期 |

同一学生在同一任务中的窗口按进入请求到达顺序接管，允许延迟的旧进入重试接管回来；心跳只能校验当前窗口，不能接管或在状态失效后重建状态。

错误响应：

| HTTP | 错误码 | 处理 |
| --- | --- | --- |
| 409 | `READING_WINDOW_REPLACED` | 停止心跳，提示“检测到其他设备或窗口正在阅读”并返回主页 |
| 410 | `READING_STATE_EXPIRED` | 停止心跳，提示刷新；包含阅读状态过期、淘汰或丢失 |
| 503 | `READING_SERVICE_UNAVAILABLE` | Redis 或数据库临时故障，按正常 30 秒节奏继续请求 |
| 401 | `UNAUTHENTICATED` | 沿用登录失效处理，提示登录或重新登录 |
| 403 | `FORBIDDEN` | 非学生调用计时接口，提示无权限 |
| 404 | `READING_TASK_NOT_FOUND` | 进入时任务不存在、不属于路径中的班级、班级已删除或学生不在班级中，统一提示“任务不存在或不可访问” |

缺少 `windowId`、UUID 格式错误或路径 ID 不合法时返回 `422`，沿用现有参数校验响应：`detail` 为数组，元素包含 `loc`、`msg`、`type` 等信息；不使用业务错误对象结构。前端按 HTTP 状态和业务错误码或字段位置处理，不匹配中文消息。

计时状态与入库规则：

- Redis 保存当前 `windowId`、整秒计时基准及过期状态；基准初始为进入时间，后续由心跳推进。PostgreSQL 只保存累计统计。不保存逐次计时明细，不向 `reading_stats` 增加临时计时字段或另建计时状态表。
- 心跳处理中，服务端原子校验状态及 `windowId`，按整秒接收时间计算差值；只要状态有效且窗口匹配，就将时间基准更新为当前时间，并重新续期 90 秒。差值为 1 到 60 秒（含边界）时，递增数据库 `reading_duration_seconds` 并更新 `updated_at`，入库成功返回 `204`；差值为零、负数或超过 60 秒时不写数据库，仍更新基准、续期并返回 `204`。不使用客户端时间戳或毫秒余数。
- 心跳发现状态失效或窗口不匹配时，分别返回 `410` 或 `409`，不修改 Redis 状态，也不写数据库。
- 时长是连续心跳的近似值：间隔不超过 60 秒时计入整个间隔，可能包含刚开始的暂停或断网时间。
- Redis 时间基准推进后数据库写入失败返回 `503 READING_SERVICE_UNAVAILABLE`，保留已推进并续期的 Redis 状态，允许少记且不补写；下一次心跳只计算新的时间间隔，不重放失败区间。数据库结果不明时不得盲目重复增加同一间隔，不增加可靠入账记录或故障补偿机制。

### 2.3 查词与加入学习

- 查词与加入学习分开处理。划词查询返回词条和带 ID 的可选释义，本身不创建卡片。
- 有结果或明确未命中均计一次查询，词典超时或故障不计；主动重复查询可累计，网络重试不重复计数。
- 同一学生的同一释义全局只加入一次，跨任务、跨班级仅一张卡片；不同学生相互独立，同一拼写的不同释义可分别建卡。
- 首次加入保存来源文章、来源任务和加入时间；服务端校验任务访问权限与释义有效性，从当前任务确定来源，不要求保存原句。
- 已有释义仅显示“已加入”，不新建卡片、不追加或更换来源、不增加数量，也不重置学习或复习进度。

### 2.4 数量口径与展示

| 指标 | 口径 |
| --- | --- |
| 任务新增学习释义数 | 该学生首次在该任务成功创建的卡片数，冗余保存为 `reading_stats.new_sense_count`，用于查询和排序 |
| 班级新增学习释义总数 | 该学生首次来源任务属于该班级的卡片数，从卡片关联任务查询，不另存班级计数 |

仅查词不增加学习释义数量。例如先在 A 任务加入、后在 B 遇到：A 计 1、B 计 0；跨班时仅 A 所属班级计 1。卡片的首次来源可用于核对和重算计数。

- 学生只看自己的任务和班级数量；老师只看学生在任务中的时长、查词次数和新增学习释义数，双方均不提供释义明细列表。
- 学生任务列表展示自己的阅读时长、查词次数和新增学习释义数；无记录显示零，不创建统计。暂不新增批量统计查询接口，获取方式待定，也不默认逐条请求。
- 老师的任务统计名单包含全部当前成员（无记录显示零），以及留有该任务历史记录的已退班学生，含零时长记录。查词或加入释义可产生零阅读时长记录，仅进入页面不会产生统计记录。

### 2.5 权限与历史保留

- 老师只能向自己的班级发布、管理任务；学生只能访问当前所属且未删除班级的任务，身份均来自登录会话。
- 新成员可读以前发布的任务，无历史时统计从零开始；退班失去访问权，保留统计、卡片及首次来源，重新加入沿用历史。
- 班级软删除保留任务、文章、统计和卡片来源。学生失去访问权，原老师通过独立只读入口查看历史统计，不通过正常班级列表或详情管理已删除班级的任务。

已打开阅读页的后续心跳按第 2.2 节处理。

## 3. 表设计

### 3.1 通用约束

- 主键使用独立自增 `BIGINT`，沿用 `BIGINT GENERATED BY DEFAULT AS IDENTITY`；不改已有班级成员等表。
- 下列字段除 `requirements`、`deleted_at` 可空且默认 `NULL` 外，均非空。
- `created_at`、`updated_at` 使用 `TIMESTAMPTZ(3)`，创建时默认当前时间，修改时显式更新相应的 `updated_at`。
- 所列外键采用 `ON DELETE RESTRICT`，不关联退班时会删除的成员记录；`sense_id` 的类型和词典外键待实际数据确定。

### 3.2 `reading_tasks`

| 字段 | 类型 | 含义与关联 |
| --- | --- | --- |
| `id` | `BIGINT` 自增 | 主键 |
| `class_id` | `BIGINT` | 所属班级 → `classes.id` |
| `article_id` | `BIGINT` | 文章 → `articles.id`，不加唯一约束 |
| `published_by` | `BIGINT` | 发布老师 → `users.id` |
| `title` | `VARCHAR(50)` | 任务标题 |
| `requirements` | `TEXT` | 可选阅读要求 |
| `created_at` | `TIMESTAMPTZ(3)` | 创建、发布时间 |
| `updated_at` | `TIMESTAMPTZ(3)` | 标题、要求或正文最近修改时间 |

### 3.3 `articles`

| 字段 | 类型 | 含义与关联 |
| --- | --- | --- |
| `id` | `BIGINT` 自增 | 主键 |
| `content` | `TEXT` | 正文 |
| `uploaded_by` | `BIGINT` | 上传老师 → `users.id` |
| `uploaded_in_class_id` | `BIGINT` | 首次上传班级 → `classes.id`，未来复用也不覆盖 |
| `created_at` | `TIMESTAMPTZ(3)` | 首次保存时间 |
| `updated_at` | `TIMESTAMPTZ(3)` | 正文最近修改时间 |

### 3.4 `reading_stats`

| 字段 | 类型 | 含义与关联 |
| --- | --- | --- |
| `id` | `BIGINT` 自增 | 主键 |
| `student_id` | `BIGINT` | 学生 → `users.id` |
| `task_id` | `BIGINT` | 任务 → `reading_tasks.id` |
| `reading_duration_seconds` | `BIGINT` | 累计阅读秒数，非负、默认 0 |
| `lookup_count` | `INTEGER` | 有效查词次数，非负、默认 0 |
| `new_sense_count` | `INTEGER` | 新增学习释义数，非负、默认 0 |
| `created_at` | `TIMESTAMPTZ(3)` | 记录创建时间 |
| `updated_at` | `TIMESTAMPTZ(3)` | 最近成功统计更新时间 |

### 3.5 `learning_cards`

| 字段 | 类型 | 含义与关联 |
| --- | --- | --- |
| `id` | `BIGINT` 自增 | 主键 |
| `student_id` | `BIGINT` | 学生 → `users.id` |
| `sense_id` | 待定 | 所选释义 |
| `source_article_id` | `BIGINT` | 首次来源文章 → `articles.id` |
| `source_task_id` | `BIGINT` | 首次来源任务 → `reading_tasks.id` |
| `created_at` | `TIMESTAMPTZ(3)` | 首次加入学习时间 |
| `deleted_at` | `TIMESTAMPTZ(3)` | 仅预留，可空、默认 `NULL` |

卡片直接保存首次来源，不另建任务生词表或多来源表，无 `updated_at`。`deleted_at` 仅预留，不实现删除、恢复或撤销加入，不改变已加入判断、来源和历史计数。DDL 等待词典确定 `sense_id` 类型，不临时假定整数或字符串。

### 3.6 唯一约束、索引与事务

- 唯一约束：统计 `(student_id, task_id)`；卡片 `(student_id, sense_id)`，覆盖全部记录。相同列组合不再重复建立普通索引。
- 普通索引：任务 `(class_id, id)`、`article_id`；统计 `(task_id, student_id)`；卡片 `(source_task_id, student_id)`、`source_article_id`。
- 创建统计：仅在合法正数时长、有效查词或首次加入释义需要写入计数时创建。普通事务内尝试插入，以 `ON CONFLICT (student_id, task_id) DO NOTHING` 处理重复，再执行独立查询取得记录；创建与本次计数更新在同一数据库事务中完成，不重置已有累计值。
- 首次加入：同一事务取得或创建统计、创建卡片并保存来源，仅实际新建卡片时原子递增 `new_sense_count`。卡片唯一约束处理重复，保持已有来源和进度、不递增计数；其他写入失败整体回滚。

## 4. 接口讨论进度

### 4.1 风格与当前边界

- 遵循 **Google AIP 风格**，保持简单，逐项确认需求。
- 沿用登录 Cookie 和服务端会话身份，不由客户端指定操作者；现有班级 API 仅供参考，本轮不重构。
- AIP 讨论方向：资源名如 `classes/10000/readingTasks/20000`，JSON 使用 `name`、`createTime`、`updateTime`，资源 ID 以字符串表达，数据库仍用 `BIGINT`。完整响应、可空字段表达及其余接口的错误结构和状态码待定，不能直接照搬现有班级 API；进入和心跳已确认的响应约定见第 2.2 节。
- 参考：[资源名 AIP-122](https://google.aip.dev/122)、[创建 AIP-133](https://google.aip.dev/133)、[更新 AIP-134](https://google.aip.dev/134)、[自定义方法 AIP-136](https://google.aip.dev/136)、[请求去重 AIP-155](https://google.aip.dev/155)、[部分响应 AIP-157](https://google.aip.dev/157)、[分页 AIP-158](https://google.aip.dev/158)。

### 4.2 发布请求去重：已确认规则

- 发布使用幂等 key 识别同一次发布操作，请求参数名为 `idempotencyKey`，保持可选。每次主动新发布生成新 key（拟用 UUID），同一次发布的重试沿用原 key；未提供时不保证去重。
- 去重状态存 Redis，以「老师 ID + idempotencyKey」识别请求并原子防止并发重复执行；不建立 PostgreSQL 去重表。文章和任务仍在同一个 PostgreSQL 事务中保存。
- Redis 去重记录采用 **60 秒滑动过期**：首次登记设置 60 秒有效期；同一老师、同一 key 每次收到重试，都将过期时间重置为本次请求起 60 秒后，处理中和已完成状态均续期。已完成状态首次写入时也重置为 60 秒。连续 60 秒没有后续请求时记录可过期，过期后相同 key 可能再次创建任务。
- Redis 区分「处理中」与「已完成」：处理中遇到重试，先续期 60 秒，再立即返回 `409 PUBLISH_IN_PROGRESS`，不等待原请求、不重复执行；客户端保留原幂等 key，不将该响应视为发布成功，也不自动重试。已完成记录保存任务 ID，重试时续期并返回原任务，不再创建文章或任务。
- 单次发布执行上限为 **10 秒**，从 Redis 首次登记 key 起算；重试续期不延长该上限。到时取消数据库操作并等待事务收尾，因此响应可能晚于 10 秒。确认事务回滚后释放对应的处理中记录；若无法确认数据库提交结果，则保留处理中状态，直到记录在连续 60 秒无请求后过期。
- 数据库确认回滚、发布超时或提交结果不明时返回 `503`。确认回滚并释放处理中记录后，客户端可保留原 key，由用户手动重试；结果不明时重试仍会按处理中规则返回 `409` 并续期。客户端不自动重试 `503`。
- 发布开始时 Redis 不可用则返回 `503`，不写 PostgreSQL。若 PostgreSQL 已确认提交，但 Redis 无法写入已完成状态，仍返回发布成功；Redis 记录可能保持处理中，过期后相同 key 可能再次创建任务。
- 不比较内容指纹，相同 key 不修改原任务。原任务若已编辑，可返回当前状态，无需保存响应快照。
- 程序崩溃等极少数故障沿用普通请求失败处理，不增加结果待确认提示、人工检查任务列表流程或专门的结果核对与恢复机制。接受数据库已提交但 Redis 尚未记录完成等故障下，去重记录过期后可能重复创建任务。
- Redis 键与字段、原子状态转换及幂等 key 格式仍待细化。

处理中重试的错误体（HTTP `409`）：

```json
{
  "detail": {
    "code": "PUBLISH_IN_PROGRESS",
    "message": "任务正在发布中"
  }
}
```

### 4.3 计时接口约定与其余接口草案

进入与心跳的路径和请求已确认；其余接口仍为草案：
